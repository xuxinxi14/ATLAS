# PPT Master：环境配置与演示文稿制作流程

## 快速复习

- **核心结论**：将解压后的项目根目录设为 Agent 工作目录，先读取仓库说明并检查环境，再开始制作。
- **核心结论**：明确区分内容来源与视觉模板；合并演示文稿时，先整理叙事和重复内容，再统一风格。
- **核心结论**：科研汇报先核对材料与结论，再生成逐页方案；交付前检查内容准确性、排版和可编辑性。

在 PowerShell 中执行，打开官方下载页面：

~~~powershell
Start-Process 'https://github.com/hugohe3/ppt-master/releases'
~~~

## 核心原理与适用场景

PPT Master 提供演示文稿制作工作流，由具备文件读写和命令执行能力的 AI Agent 调用。模型负责理解材料、组织内容和设计页面，项目中的脚本负责相应处理与导出；具体能力和依赖以所下载版本为准。参见[官方仓库说明](https://github.com/hugohe3/ppt-master)。

原笔记中的 harness 指承载模型并提供工具能力的运行环境，例如 WorkBuddy、Codex 或 Claude Code。使用时应让 Agent 能够访问项目目录、读取参考材料并执行所需命令。

适用场景：

- 将两份或多份 PPT 合并，去除重复内容并统一叙事与视觉风格。
- 基于 Word、PDF、图片或网页资料制作课程作业、项目介绍与组会汇报。
- 先与 AI 讨论研究问题，再将确认后的内容整理成逐页演示方案。
- 根据已有模板制作初稿，再对字号、配色、图片和信息密度进行迭代。

不宜直接采用生成结果的情况：

- 原始材料存在相互矛盾的数据或尚未确认的实验结论。
- 要求严格保留原稿全部动画、母版或复杂对象，但尚未验证转换效果。
- 只有普通聊天能力，无法访问本地文件或运行项目脚本。

> [!IMPORTANT]
> “能够生成 PPT”不等于“科研内容已经核实”。数据、引用、实验状态与结论强度仍需逐项核对。

## 标准操作流程

1. **下载项目并确认根目录**

   输入：从[官方 Releases 页面](https://github.com/hugohe3/ppt-master/releases)下载的项目 ZIP 包。

   操作：解压后定位项目根目录，避免误选 ZIP 文件或外层空目录。以下以 `D:\ppt-master` 为示例，执行前替换成实际路径。

   ~~~powershell
   Set-Location -LiteralPath 'D:\ppt-master'
   Get-ChildItem -Force
   Test-Path -LiteralPath '.\requirements.txt'
   ~~~

   预期反馈：可以看到仓库说明和项目文件；完整仓库通常包含 `requirements.txt`。若返回 `False`，先核对目录及下载包说明。

2. **检查 Python 并安装依赖**

   输入：项目根目录，以及符合所下载版本要求的 Python 环境。

   以下命令使用 Windows Python 启动器 `py`，通过项目虚拟环境安装依赖：

   ~~~powershell
   py -3 --version
   py -3 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   .\.venv\Scripts\python.exe -m pip check
   ~~~

   预期反馈：Python 版本符合要求，安装命令成功结束，`pip check` 未报告依赖冲突。

   > [!NOTE]
   > 官方仓库当前说明要求 Python 3.10 及以上。上述命令直接调用虚拟环境解释器，无需运行激活脚本；其余依赖按所下载版本的说明补齐。

3. **在 Agent 中打开项目并完成环境检查**

   输入：已解压的项目目录。

   操作：在 harness 中创建项目或打开文件夹，将实际项目根目录设为工作目录，然后发送：

   ~~~text
   分析当前仓库内容，为后续 PPT 任务准备运行环境。
   先读取仓库说明及适用的工作流指引，确认项目根目录、Python 解释器、
   依赖状态、制作入口和导出位置。
   使用当前项目的 .venv 环境执行 Python 命令。
   检查完成后列出可用能力与尚未解决的问题。
   ~~~

   预期反馈：Agent 能说明所读取的文件、使用的解释器、环境检查结果及下一步入口。

4. **准备材料并说明需求**

   输入：内容文档、现有 PPT、视觉模板、图片，以及必要的网页链接。

   操作：将材料放入当前项目中的明确目录，或通过 harness 上传。建议为每个任务分别保存原始材料，并在提示中提供实际路径。

   ~~~text
   请先读取我提供的全部材料，并列出文件清单。
   内容来源：[文档与演示文稿的实际路径]
   视觉模板：[模板的实际路径；没有则说明]
   参考网页：[完整 URL；无法访问时请明确指出]

   汇报者身份：[填写]
   听众与使用场景：[填写]
   汇报目标：[填写]
   时长与目标页数：[填写]
   偏好风格：[填写]
   必须保留的内容：[填写]
   输出要求：可编辑 PPTX，列出最终文件路径。
   ~~~

   预期反馈：Agent 正确区分内容来源与视觉参考，并形成与汇报目标一致的制作方案。

   > [!TIP]
   > 网页链接不是本地文件。提供完整 URL，并确认 Agent 实际读取成功；如果无法访问，可补充导出的 PDF 或网页正文。

5. **场景一：合并两份 PPT 并统一风格**

   输入：两份内容 PPT，以及一份用于视觉参考的模板。

   操作：先要求整理内容和页序，再制作演示文稿。

   ~~~text
   请合并两份内容 PPT，以第三份 PPT 作为视觉参考。
   先列出内容来源、重复内容、冲突信息及建议页序。
   保留原始事实、数据和引用；无法判断的冲突请单独列出。
   确认内容结构后，统一字体、配色、标题层级和页面布局。
   如需生成配图，请确保配图不被当作真实人物照片或实验结果。
   完成后导出可编辑 PPTX，并列出需要人工复核的页面。
   ~~~

   预期反馈：形成连贯的合并稿，重复内容得到处理，视觉风格统一，关键内容可追溯。

6. **场景二：先讨论研究材料，再制作组会 PPT**

   输入：项目说明、研究方案、实验记录或阶段性结果。

   操作：先解读材料，讨论研究逻辑和汇报重点，再生成演示方案。

   ~~~text
   请阅读项目材料，先提供项目总结和关键名词解释。
   将材料中的事实、已有结果、待验证假设和建议分别说明。
   我们先讨论研究目标、实施路径与当前问题，暂不制作 PPT。
   ~~~

   讨论完成后继续发送：

   ~~~text
   请根据已经确认的讨论内容，整理一份组会 PPT 制作方案。
   每页写明标题、核心信息、证据来源和建议图示。
   明确区分已完成工作、待验证假设及后续计划。
   先输出方案供我核对，通过后再使用当前仓库制作可编辑 PPTX。
   ~~~

   预期反馈：先获得可核对的逐页方案，再据此生成演示文稿。

   > [!IMPORTANT]
   > 如果讨论结论是不需要引入 AI，就按该结论组织汇报。不要为了突出工具而添加缺乏必要性或证据的 AI 模块。

7. **逐页检查并按具体问题微调**

   输入：生成的 PPTX，以及需要修改的页码和元素。

   操作：打开实际文件，检查内容与视觉效果，再提交范围明确的修改指令。

   ~~~text
   请在当前版本上调整：
   8. 增大正文字号，并重新检查换行与文本框溢出。
   9. 删除首页指定的红点装饰。
   10. 保留已经核对通过的正文、数据、引用和讲者备注。
   修改后重新检查全部页面，并另存为新版本 PPTX。
   ~~~

   预期反馈：指定问题得到修正，未引入内容遗漏、遮挡或新的排版问题。

## 常见排障与避坑指南

> [!NOTE]
> 原笔记未记录实际安装报错。以下结合操作步骤与示例整理易错点，其中环境故障属于预防性排查。

- **找不到 `requirements.txt` → 工作目录错误，或下载包结构不同 →** 执行 `Get-Location` 和 `Get-ChildItem -Force`，定位真实根目录后再运行安装命令。

- **提示无法识别 `py` → Windows Python 启动器不可用 →** 执行 `python --version` 检查解释器；若版本合适，可改用 `python -m venv .venv`，随后仍调用 `.venv\Scripts\python.exe` 安装依赖。

- **依赖安装成功但 Agent 仍报缺少模块 → 安装与运行使用了不同解释器 →** 执行 `.\.venv\Scripts\python.exe -m pip check`，并要求 Agent 使用同一解释器重试原命令。

- **Agent 找不到材料 → 文件未上传成功、路径错误或目录不可访问 →** 使用 `Test-Path -LiteralPath '材料的实际完整路径'` 检查，再将准确路径交给 Agent。

- **合并后内容重复或前后矛盾 → 只要求拼接页面，没有先整理内容 →** 发送“先列出重复与冲突信息，核对后重组页序，再统一风格”。

- **组会稿将计划写成成果 → 未区分实验状态与推测 →** 发送“逐页区分已完成结果、待验证假设与后续计划，并标注证据来源”。

- **字体太小或装饰干扰阅读 → 单页信息过多，或模板元素不适合当前内容 →** 发送“指定页增大字号、拆分过密内容、删除指定装饰，并检查溢出”，不要只要求整体美化。

- **ZIP 下载的项目无法执行 `git pull` → 解压目录没有 Git 历史 →** 从官方页面下载新版本并解压到新目录，迁移工作文件和必要配置后重新安装依赖。

- **文件已生成但无法正常交付 → 只检查了导出成功，未检查实际打开效果 →** 用目标演示软件打开 PPTX，逐页检查字体、图片、备注与对象编辑情况。

## 验证清单

- [x] 掌握环境检查标准：项目根目录正确，Python 版本符合要求，安装与运行使用同一解释器。
- [x] 掌握输入准备标准：内容来源、视觉模板和汇报目标分别明确，材料可被 Agent 实际读取。
- [x] 掌握内容验收标准：数据与引用可追溯，已完成结果、假设和计划没有混淆。
- [x] 掌握交付验收标准：实际打开 PPTX 逐页检查，确认关键对象可编辑且无文本溢出、遮挡或图片缺失。
