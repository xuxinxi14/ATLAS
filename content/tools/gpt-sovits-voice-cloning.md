# GPT-SoVITS 本地语音克隆与音质优化操作手册

## 快速复习

- **核心结论**：RTX 5060 8GB 显存可以运行 GPT-SoVITS，优先使用适配 NVIDIA 50 系显卡的整合包，避免旧版 CUDA 环境不兼容。
- **核心结论**：首次使用应进入 `1-GPT-SoVITS-TTS → 1C-推理`，使用 3～10 秒清晰参考音频进行零样本语音克隆，不需要提前训练模型。
- **核心结论**：生成声音模糊、咬字粘连时，优先检查参考音频静音、文本匹配、模型版本与语言模式，再调整语速和切分参数。

在 GPT-SoVITS 整合包的解压根目录打开 PowerShell，执行：

~~~powershell
.\go-webui.bat
~~~

预期结果：启动 GPT-SoVITS WebUI，之后在 TTS 页签开启推理服务。

## 核心原理与适用场景

### 1. GPT-SoVITS 是什么

GPT-SoVITS 是一个支持少样本声音克隆的语音合成系统，主要用于：

- 文本转语音（Text-to-Speech，TTS）。
- 零样本声音克隆（Zero-shot Voice Cloning）。
- 少样本模型微调（Few-shot Fine-tuning）。
- 跨语言语音合成。
- 配合预处理工具建立语音训练数据集。

其基本工作流程为：

**参考音频 → 提取说话人相关语音特征 → 输入目标文本 → 生成具有相似音色的新语音。**

其中：

- **GPT 部分**：主要负责语音相关语义表示的预测。
- **SoVITS 部分**：主要负责根据预测结果合成语音波形。
- **参考音频**：提供说话人的音色、韵律等参考信息。
- **参考文本**：帮助模型建立参考语音与语言内容之间的对应关系。

零样本克隆不等于完整学习了一个人的声音。其相似度、咬字和自然程度仍然受到参考素材和底模能力的限制。

### 2. 两种主要使用模式

| 模式 | 所需素材 | 特点 | 适用场景 |
|---|---|---|---|
| Zero-shot | 约 5 秒参考音频 | 无需训练，直接推理 | 快速体验、音色测试 |
| Few-shot | 约 1 分钟或更多训练数据 | 需要微调，通常有机会提高相似度和稳定性 | 长期配音、固定角色音色 |

> [!NOTE]
> 官方支持使用少量音频完成微调，但不保证微调后一定优于零样本推理。训练素材的质量、数量、标注准确性和参数都会影响结果。

### 3. 本地硬件适配

当前使用的电脑环境：

| 硬件 | 配置 | 适用性 |
|---|---|---|
| GPU | RTX 5060 Laptop | 支持本地 GPU 推理 |
| 显存 | 8GB GDDR7 | 适合零样本推理及受限规模的微调 |
| 内存 | 16GB | 基本够用，多程序并行可能不足 |
| 存储 | 1TB SSD | 可存放整合包、预训练模型及训练数据 |
| 操作系统 | Windows | 支持 Windows 整合包 |

RTX 5060 属于 NVIDIA Blackwell 架构。

该架构需要使用兼容的 PyTorch 和 CUDA 构建版本。PyTorch 2.7 配合 CUDA 12.8 是支持 Blackwell 的环境组合之一。

此前使用的安装包为 NVIDIA 50 系适配版本：

`GPT-SoVITS-v2pro-20250604-nvidia50.7z`

> [!IMPORTANT]
> 整合包名称包含 v2Pro，不代表推理时一定选择了 v2Pro 权重。实际使用的模型必须在推理页面检查。已经正常运行的整合包不应仅为调音质而随意重装 CUDA 或 PyTorch。

### 4. WebUI 各模块的作用

| 模块 | 主要功能 | 首次使用是否需要 |
|---|---|---|
| 0a-UVR5 | 人声与伴奏分离 | 否 |
| 0b-语音切分 | 长录音自动分段 | 否 |
| 0c-ASR | 将语音自动识别为文字 | 否 |
| 0d-文本校对 | 修正语音识别标注 | 否 |
| 1A-训练集格式化 | 将音频和文本处理为训练数据 | 否 |
| 1B-微调训练 | 训练 GPT 和 SoVITS 模型 | 否 |
| 1C-推理 | 输入文本并生成语音 | 是 |
| 2-变声 | 已有语音的音色转换 | 否 |

零样本推理只需要 `1C-推理`。

需要训练时，完整流程通常为：

**原始录音 → 可选人声分离 → 音频切片 → ASR → 文本校对 → 数据集格式化 → 模型微调 → 推理。**

### 5. 参考音频为什么会影响生成效果

参考音频会为模型提供音色和发音特征，但并非所有满足时长要求的音频都适合推理。

较理想的参考音频通常具有：

- 3～10 秒的总时长，推荐优先测试约 5～8 秒的完整语音。
- 单人说话，吐字清晰。
- 无明显背景音乐、噪声及混响。
- 正常语速，不刻意拖长或压缩发音。
- 开头与结尾没有大段无意义静音。
- 参考文本和实际说话内容尽可能准确对应。

WAV 通常适合保存清晰的参考素材，但文件格式本身并不能保证音质。

## 标准操作流程

### 1. 启动本地 WebUI

1. 解压适配 NVIDIA 50 系显卡的 GPT-SoVITS 整合包。
2. 进入解压后的程序根目录。
3. 双击 `go-webui.bat`，或在该目录使用快速复习中的 PowerShell 命令。
4. 等待程序启动并打开 WebUI。

预期反馈：能够看到 GPT-SoVITS 控制台以及数据处理、TTS、变声等模块。

> [!TIP]
> 如果已经成功运行 GPU 推理，说明至少当前使用的主要计算环境可用，不必因为生成声音不好听就重新安装程序。

### 2. 准备参考音频

建议录制或截取一段清晰中文语音，例如：

“今天下午我准备去图书馆，顺便把最近的实验资料整理一下。”

操作要求：

1. 选取约 5～8 秒的有效语音。
2. 删除明显多余的前置和尾部静音。
3. 避免切断句首或句尾音素。
4. 保存为 WAV，保留正常音量，不进行过度降噪。
5. 准确记录录音中说出的文字。

本次实际测试曾使用以下参考文本：

“过去与未来如此相似，我却对此无动于衷。”

对应的原始音频约 6.97 秒，前面存在约 2.14 秒静音。此前已经裁剪出约 4.76 秒的 WAV 版本。

这说明音频总时长符合要求，不代表有效人声比例一定合适。

> [!WARNING]
> 裁剪静音是值得优先尝试的改进措施，但不能仅凭存在静音就认定其必然是声音模糊的根本原因。

### 3. 进入 TTS 推理页面

1. 点击 `1-GPT-SoVITS-TTS`。
2. 找到 `1C-推理`。
3. 检查 GPT 模型和 SoVITS 模型的选项。
4. GPU 设备编号使用 `0`（单 NVIDIA 显卡环境通常如此）。
5. 开启 TTS 推理 WebUI。
6. 等待底模加载完成。

预期反馈：出现独立的语音推理界面，能够上传参考音频并输入目标文本。

### 4. 检查模型版本

当前安装包主要面向 v2Pro 系列。

应重点检查 SoVITS 模型文件名，例如：

| 模型文件 | 对应版本 |
|---|---|
| `s2G2333k.pth` | v2 系列 |
| `s2Gv2Pro.pth` | v2Pro |
| `s2Gv2ProPlus.pth` | v2ProPlus |

v2Pro 系列预训练模型一般存放在：

`GPT_SoVITS/pretrained_models/v2Pro/`

操作时应在 WebUI 中选择对应版本提供的预设模型，并检查其 GPT 与 SoVITS 权重是否为支持的组合。

> [!IMPORTANT]
> 不要任意混搭不同版本的 GPT 和 SoVITS 权重。模型组合应以当前整合包的版本预设和官方说明为准。

### 5. 填写参考信息

本次使用的示例：

| 设置 | 输入 |
|---|---|
| 参考音频 | 裁剪后的 WAV 文件 |
| 参考文本 | 过去与未来如此相似，我却对此无动于衷。 |
| 参考语言 | 中文 |
| 无参考文本模式 | 关闭 |

注意：

- 参考文本应与录音内容一致。
- 不能漏字、随意改写或省略口头语。
- 即使输入的是中文语音，也要检查参考语言选择。
- 有准确文本时，优先使用正常的有参考文本模式。

预期反馈：推理程序正确读取参考音频及其文本信息。

### 6. 填写目标文本

第一次建议只使用中文，避免中英文混合造成额外干扰。

推荐测试文本：

“你好，今天天气非常不错。我准备下午去图书馆，看一看最近整理的实验资料。”

推荐参数：

| 参数 | 初始建议 |
|---|---|
| 目标语言 | 中文 |
| 语速 | 1.0 |
| 句间停顿 | 0.3～0.4 秒 |
| 文本切分 | 按中文标点切分 |
| top_k | 默认 |
| top_p | 默认 |
| temperature | 默认 |

点击合成语音。

预期反馈：生成可以播放、保存的音频文件，使用与参考声音相似的音色朗读目标文本。

### 7. 测试中英文混合

纯中文测试正常后，再使用混合文本：

“你好。我现在正在测试 GPT SoVITS。这是由人工智能生成的语音。”

建议：

1. 将目标文本语言切换为中英混合。
2. 将长句拆分为短句。
3. 英文名称两侧适当留空格。
4. 必要时将英文术语改成更容易被前端处理的形式。
5. 对比新旧生成结果。

注意：`GPT-SoVITS` 改写成 `GPT SoVITS` 是一种排障实验，不保证所有版本都会因此获得更好的英文发音。

### 8. 进一步优化声音

如果声音仍不清晰：

1. 固定相同的目标文本。
2. 使用裁剪后的参考音频重新生成。
3. 检查模型是否为 v2Pro。
4. 若整合包支持，使用 v2ProPlus 进行对照测试。
5. 每次只更改一个参数，保存生成结果。
6. 对比咬字、音色、语速和自然程度。

可尝试将语速从 `1.0` 调整至 `0.9`，但不应把降低语速当成解决声音模糊的通用方法。

如果合理优化后仍不能满足需求，再考虑用更多合规录音素材进行少样本微调。

### 9. 需要微调时的数据准备

训练数据一般需要音频片段及对应文字。

典型的 `.list` 标注格式：

`音频路径|说话人名称|语言代码|文字内容`

例如：

`D:\VoiceData\001.wav|speaker01|zh|今天天气非常不错。`

其中：

- `音频路径`：实际音频文件位置。
- `speaker01`：说话人标识。
- `zh`：中文语言代码。
- `文字内容`：与音频对应的转录文本。

实际步骤：

1. 将原始长录音导入切片工具。
2. 使用 ASR 自动生成文本。
3. 人工校对错字、漏字和标点。
4. 在 `1A` 中格式化训练数据。
5. 在 `1B` 中执行模型微调。
6. 使用训练后的模型进入 `1C` 测试。

> [!CAUTION]
> 声音克隆应使用自己的声音或已获得明确授权的素材。公开发布生成音频时，应避免使听众误认为是真实人物亲自录制或认可的发言。

## 常见排障与避坑指南

### 1. 生成音频非常模糊，咬字粘连

**现象 →**

能够生成语音，但声音偏闷，辅音不清楚，字词之间像粘在一起。

**可能原因 →**

- 参考音频质量不理想。
- 参考音频存在过长静音。
- 参考文字与实际录音不匹配。
- 实际使用的底模不符合预期。
- 零样本模型对该音色的泛化能力有限。
- 中英文前端处理或分句方式不合适。

**解决操作 →**

1. 去除参考音频中明显过长的静音。
2. 检查参考文本是否逐字对应。
3. 使用纯中文短句进行测试。
4. 确认模型权重和版本。
5. 恢复语速 `1.0` 及默认采样参数。
6. 对比 v2Pro 和 v2ProPlus 的实际输出。

本次参考音频已发现开头存在较长静音，但尚不能证明它是唯一原因。

### 2. 降低语速后仍然模糊

**现象 →**

把语速从 `1.0` 调整为 `0.9`，甚至更低，声音仍然含糊。

**原因 →**

语速控制主要改变语音的时间尺度，并不等同于修复音素细节。

**解决操作 →**

恢复语速 `1.0`，优先处理参考音频及模型选择。

如果只存在讲话偏快的问题，再小幅降低语速。

### 3. 中英文名称发音不自然

**现象 →**

中文部分相对正常，但 `GPT-SoVITS` 等术语发音混乱。

**可能原因 →**

使用了纯中文语言模式，或文本前端对混合字符、连字符的处理不理想。

**解决操作 →**

1. 将目标语言改为中英混合。
2. 尝试使用 `GPT SoVITS`。
3. 使用中文标点明确分句。
4. 先测试纯中文，再加入英文。

### 4. 句子之间没有明显停顿

**现象 →**

多句话连续输出，缺乏自然停顿。

**可能原因 →**

文本切分方式不合适、标点不足，或句间间隔设置偏短。

**解决操作 →**

1. 将长文本拆分为完整短句。
2. 使用句号而不是全部使用逗号。
3. 选择适当的文本切分方式。
4. 如果界面支持，尝试将句间间隔设为 `0.4～0.5` 秒。

注意：句间停顿参数通常不能直接修复一句话内部的咬字不清。

### 5. 参考音频长度不合适

**现象 →**

上传参考音频后出现长度相关报错。

**原因 →**

推理模式通常要求主参考音频在 3～10 秒范围内。

**解决操作 →**

截取一段完整清晰语句，控制总时长在该范围内，优先测试 5～8 秒左右。

不要为了满足时长而补充大段静音。

### 6. NVIDIA 50 系显卡 CUDA 不兼容

**现象 →**

程序无法使用 GPU，或者出现类似：

`no kernel image is available for execution`

`sm_120 is not compatible`

**可能原因 →**

使用了不支持 Blackwell 架构的旧版 PyTorch/CUDA 构建。

**解决操作 →**

优先使用 NVIDIA 50 系专用整合包。

若选择从源码搭建，则应安装支持 Blackwell 的 PyTorch/CUDA 组合，例如经官方支持的 PyTorch 2.7 + CUDA 12.8 环境。

不要直接把旧教程中的 CUDA 11.8 环境用于 RTX 5060。

### 7. 整合包是 v2Pro，实际模型却是 v2

**现象 →**

安装包名称含有 `v2Pro`，但生成效果与预期不符。

**原因 →**

程序版本与当前选择的推理权重不是同一个概念。

**解决操作 →**

在 `1C-推理` 查看 GPT 和 SoVITS 模型列表，检查是否选择了 `s2Gv2Pro.pth` 等预期模型。

如需切换，按当前版本要求选择匹配的模型组合。

### 8. 16GB 内存环境容易占满资源

**现象 →**

模型加载缓慢、程序卡顿，或者多个 AI 工具同时运行时发生内存不足。

**可能原因 →**

系统内存同时被 GPT-SoVITS、浏览器、VS Code、LM Studio 等程序占用。

**解决操作 →**

1. 关闭其他大型 AI 程序。
2. 优先只运行一个推理服务。
3. 训练时适当减少 batch size。
4. 使用任务管理器查看系统内存和 GPU 显存占用。

如果长期进行模型训练，32GB 内存会更宽裕，但不是零样本推理的必要条件。

### 9. 不应过度依赖一次生成结果

**现象 →**

同样的参考声音，某次结果咬字不清，另一次相对自然。

**原因 →**

语音生成过程具有一定随机性，采样参数也会影响输出。

**解决操作 →**

- 固定目标文本与参考音频。
- 保留默认参数作为基线。
- 多次生成，比较结果稳定性。
- 每次只修改一个变量。
- 保存不同底模的对照音频。

不要在一次实验中同时修改模型、语速、语言模式、参考音频和采样参数，否则难以判断是哪项调整起作用。
