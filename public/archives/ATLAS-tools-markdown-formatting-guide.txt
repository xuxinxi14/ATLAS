核心原理与适用场景

1. Markdown 是什么

Markdown 是一种轻量级标记语言，通过简单的纯文本符号描述文档结构和排版格式。

例如：

~markdown
这是粗体文本
~

Markdown 渲染器会将其解析为加粗文本，而不是直接显示两侧的星号。

其工作过程为：

1. 编写包含 Markdown 标记的纯文本。
2. Markdown 解析器识别标题、列表、代码等结构。
3. 渲染器将内容转换为对应的显示效果。
4. 用户在编辑器、网页或文档阅读器中查看结果。

Markdown 文件通常使用 .md 扩展名，本质上是可以被普通文本编辑器打开的文件。

2. Markdown 的适用场景

常见用途包括：

- 个人知识库：Obsidian、ATLAS 等。
- 开源项目文档：GitHub README、开发指南、技术手册。
- 科研笔记：实验记录、分析流程、文献整理。
- 软件开发：项目说明、CHANGELOG、操作指南。
- 学习资料：课程笔记、知识总结、复习提纲。

Markdown 特别适合以文本为主、需要版本管理或长期维护的文档。

对于高度复杂的印刷排版、多栏设计以及精确页眉页脚控制，Word、LaTeX 等工具可能更加合适。

3. Markdown 标准与扩展

不同软件对 Markdown 的支持范围可能不同。

| 类型 | 特点 | 典型功能 |
|---|---|---|
| CommonMark | 规范化的基础 Markdown 语法 | 标题、强调、引用、列表、代码 |
| GFM | GitHub 扩展语法 | 表格、任务列表、删除线 |
| Obsidian 扩展 | 面向个人知识管理 | 高亮、双链、嵌入、提示框 |
| LaTeX / MathJax 扩展 | 数学公式排版 | 行内公式、块级公式 |

> [!IMPORTANT]
> Markdown 并非在所有软件中完全一致。编写需要跨平台使用的文档时，应优先采用 CommonMark 和 GFM 中广泛支持的语法。

标准操作流程

1. 标题语法

标题用于组织文档层级，最多支持六级。

基本格式：

+ 空格 + 标题文字

完整示例：

~markdown
一级标题

二级标题

三级标题

四级标题

五级标题

六级标题
~

语法说明：

| 标记 | 层级 | 常见用途 |
|---|---|---|
| # | 一级标题 | 文档主标题 |
| ## | 二级标题 | 主要章节 |
| ### | 三级标题 | 章节中的子主题 |
| #### | 四级标题 | 进一步细分 |
| ##### | 五级标题 | 详细内容 |
| ###### | 六级标题 | 最细层级 |

> [!TIP]
> 一篇笔记通常只需要一个一级标题，正文主要使用二级和三级标题即可。过深的标题层级会降低可读性。

注意：

- #标题 不符合标准 ATX 标题语法，应写成 # 标题。
- 标题标记后需要空格或制表符。
- 不支持七级标题。
- 建议在标题前后保留空行，增强兼容性与可读性。

2. 文本标记语法

Markdown 可以为文字添加粗体、斜体、删除线等样式。

| 效果 | 语法 | 说明 |
|---|---|---|
| 加粗 | 文本 | 强调重要信息 |
| 斜体 | 文本 | 术语、补充强调 |
| 粗斜体 | 文本 | 同时加粗和倾斜 |
| 删除线 | 文本 | 表示删除或废弃 |
| 高亮 | 文本 | Obsidian 等软件支持 |
| 行内代码 | 单反引号包围文本 | 命令、变量、文件名 |

完整示例：

~markdown
重要内容

斜体内容

特别重要的内容

已经废弃的内容

需要记住的重点

使用 print() 函数输出信息。
~

预期显示：

- 加粗文字会使用更粗的字重。
- 斜体文字会倾斜。
- 删除线文字中间出现横线。
- 支持高亮的渲染器会显示背景颜色。
- 行内代码通常使用等宽字体。

> [!NOTE]
> 高亮 不是 CommonMark 的标准语法。Obsidian 支持它，但 GitHub 等平台不一定会将其渲染为高亮。

3. 文本选择与快捷键

在 Windows 中，以下快捷键可提高编辑效率。

| 快捷键 | 功能 |
|---|---|
| Shift + ← / → | 向左或向右逐字符选中文字 |
| Ctrl + Shift + ← / → | 按单词或词组扩展选择 |
| Shift + Home | 选中至当前行开头 |
| Shift + End | 选中至当前行结尾 |
| Ctrl + A | 全选文本 |
| Ctrl + B | 加粗选中文本（支持的编辑器） |
| Ctrl + I | 将选中文本设为斜体（支持的编辑器） |
| Ctrl + C | 复制 |
| Ctrl + V | 粘贴 |
| Ctrl + Z | 撤销 |
| Ctrl + Y | 重做（部分编辑器） |
| Ctrl + L | 功能因编辑器和快捷键配置而异 |

使用方法：

1. 将光标移动到目标文字附近。
2. 按住 Shift 并使用方向键选择文字。
3. 按 Ctrl + B 或 Ctrl + I。
4. 检查编辑器是否自动添加 Markdown 标记。

例如：

~markdown
原始文字：
Markdown 很重要

选中“很重要”后加粗：
Markdown 很重要
~

> [!WARNING]
> Ctrl + L 不是 Markdown 通用的复选框快捷键。若在 Obsidian 中需要快速切换任务列表，可以在「设置 → 快捷键」中搜索对应命令，查看或自定义快捷键。

> [!NOTE]
> 小键盘方向键受到 Num Lock 状态影响。文字选择建议直接使用独立方向键。

4. 无序列表

无序列表适合记录要点、功能清单或知识分类。

语法：

- + 空格 + 列表内容

示例：

~markdown
- 第一个要点
- 第二个要点
- 第三个要点
~

除 - 外，也可以使用  或 +。

例如：

~markdown
 第一个要点
 第二个要点
~

推荐统一使用 -，方便长期维护。

多级嵌套列表

通过缩进可以建立层级关系。

~markdown
- 微生物学
  - 细菌
    - 革兰氏阳性菌
    - 革兰氏阴性菌
  - 真菌
    - 酵母菌
    - 霉菌
~

建议每层使用两个或四个空格，保持同一文档中的缩进风格一致。

5. 有序列表

有序列表适合实验步骤、操作流程、阶段计划等。

语法：

数字 + . + 空格 + 内容

示例：

~markdown
1. 打开软件
2. 创建项目
3. 导入文件
4. 保存结果
~

在标准 Markdown 中，有序列表的源文件数字不一定决定最终显示的连续编号。

例如：

~markdown
1. 第一步
1. 第二步
1. 第三步
~

通常仍会渲染为连续编号。

> [!TIP]
> 需要经常插入或删除步骤时，可以统一使用 1.，由 Markdown 渲染器自动编号。但为了方便阅读源文件，也可以手动使用连续数字。

6. 任务列表与复选框

任务列表属于 GFM 等扩展语法。

未完成：

~markdown
- [ ] 阅读文献
~

已完成：

~markdown
- [x] 阅读文献
~

完整示例：

~markdown
今日任务

- [x] 整理课程笔记
- [x] 完成实验记录
- [ ] 阅读两篇论文
- [ ] 编写项目文档
~

注意：

- - 后需要空格。
- [ ] 内部需要保留空格。
- [x] 表示已完成。
- 不同 Markdown 软件对复选框的交互支持不同。

7. 引用块

引用用于标记引用资料、重点说明等内容。

语法：

> + 空格 + 内容

示例：

~markdown
> 这是引用内容。
~

多行引用：

~markdown
> 第一行引用内容。
> 第二行引用内容。
> 第三行引用内容。
~

嵌套引用：

~markdown
> 一级引用
>
> > 二级引用
~

引用块不会自动创建文献来源。引用论文时，应额外标明出处。

8. GitHub 风格提示框（Callout）

提示框用于突出重要信息。

基本语法：

~markdown
> [!NOTE]
> 这里是补充说明。

> [!TIP]
> 这里是操作建议。

> [!IMPORTANT]
> 这里是重要信息。

> [!WARNING]
> 这里是风险提醒。

> [!CAUTION]
> 这里是需要谨慎处理的内容。
~

常见类型：

| 类型 | 主要用途 |
|---|---|
| [!NOTE] | 补充信息 |
| [!TIP] | 使用技巧 |
| [!IMPORTANT] | 必须注意的内容 |
| [!WARNING] | 潜在风险 |
| [!CAUTION] | 高风险操作或注意事项 |

> [!IMPORTANT]
> ATLAS 笔记建议优先使用以上五种提示框类型。虽然 Obsidian 支持更多类型，但 ATLAS 的实际兼容性应以编译器支持范围为准。

9. 分隔线

分隔线用于区分不同内容区域。

常用语法：

~markdown
---
~

也可以使用：

~markdown
*
~

或：

~markdown
___
~

推荐使用 ---，并在前后保留空行。

注意：在 Markdown 文件开头，--- 还可能用于标识 YAML Front Matter 的开始和结束。

10. 行内代码与代码块

行内代码

使用一对反引号包围文字。

示例：

~markdown
使用 python 运行程序。

文件名为 README.md。

执行 git status 查看状态。
~

适合表示：

- 命令名称
- 变量名称
- 文件名
- 配置字段
- 简短代码片段

多行代码块

使用三个反引号开始和结束代码块。

在起始反引号后可以指定语言，以启用语法高亮。

Python 示例：

~python
def hello():
    print("Hello, World!")

hello()
~

Bash 示例：

~bash
git status
git add .
git commit -m "Update docs"
~

PowerShell 示例：

~powershell
Get-Location
Get-ChildItem
~

常见语言标识：

| 标识 | 对应语言 |
|---|---|
| python | Python |
| bash | Bash / Shell |
| powershell | PowerShell |
| javascript | JavaScript |
| typescript | TypeScript |
| json | JSON |
| yaml | YAML |
| html | HTML |
| css | CSS |
| markdown | Markdown |
| sql | SQL |
| r | R |

> [!TIP]
> Markdown 代码块也可以使用三个波浪号 ~ 作为围栏，其作用与三个反引号类似。在编写需要展示 Markdown 代码的教程时，可以交替使用两种围栏，避免嵌套冲突。

11. 超链接语法

基本格式：

显示文字

示例：

~markdown
GitHub 官网

Obsidian 官网
~

也可以使用 Markdown 文件的相对路径链接：

~markdown
查看使用教程
~

添加悬停标题：

~markdown
GitHub
~

链接路径应根据实际文件结构填写。

12. 图片插入语法

Markdown 图片语法与超链接相似，但前面多一个 !。

格式：

替代文字

外部图片：

~markdown
项目 Logo
~

本地图片：

~markdown
实验流程图
~

相对路径说明：

- ./：当前目录。
- ../：上一级目录。
- images/：当前目录下的 images 文件夹。

> [!NOTE]
> 图片替代文字用于描述图片内容，在图片无法加载或辅助技术读取时尤其重要。不要将图片替代文字仅当作装饰性标题。

13. Markdown 表格

表格适合展示参数、数据对比和知识速查。

基本语法：

~markdown
| 名称 | 功能 | 状态 |
|---|---|---|
| Python | 数据分析 | 已掌握 |
| R | 统计分析 | 学习中 |
| Git | 版本控制 | 已掌握 |
~

表格包含三个基本部分：

1. 表头。
2. 使用连字符分隔的表头分隔行。
3. 表格数据行。

表格文字对齐

使用冒号控制对齐方式。

~markdown
| 左对齐 | 居中 | 右对齐 |
|:---|:---:|---:|
| A | B | C |
| 100 | 200 | 300 |
~

说明：

- :---：左对齐。
- :---:：居中。
- ---:：右对齐。

> [!WARNING]
> 表格中的竖线 | 是列分隔符。如果单元格正文需要显示竖线，应写成 \|，否则可能导致表格结构错乱。

14. 换行与段落

Markdown 的换行与普通文本编辑器有所区别。

新段落

两个段落之间保留一个空行。

~markdown
这是第一段。

这是第二段。
~

强制换行

在行末添加两个空格后换行，或使用反斜杠：

~markdown
第一行\
第二行
~

这种写法在 CommonMark 中表示硬换行。

> [!NOTE]
> 单次按下 Enter 通常只会在源文件中产生新行，不一定在最终渲染结果中形成可见换行。部分编辑器会根据设置修改这一行为。

15. 转义特殊字符

Markdown 的特殊符号可能被解析为格式标记。

使用反斜杠 \ 可以转义大多数 Markdown 标点符号。

示例：

~markdown
\# 这里不是标题

\这里不会变成斜体\

\\这里不会变成粗体\\

1\. 这里不会自动生成有序列表
~

常见需要转义的符号：

| 原始符号 | 转义写法 |
|---|---|
| # | \# |
|  | \ |
| _ | \_ |
| | | \| |
| ~ | \~ |
| [ | \[ |
| ] | \] |

16. 数学公式（扩展语法）

Obsidian 等支持数学渲染的软件可以使用 LaTeX 语法。

行内公式

使用单个美元符号包围公式。

~markdown
圆的面积公式为 S=\pi r^2。
~

独立公式

使用两个美元符号包围公式。

~markdown

E=mc^2

~

更复杂的公式：

~markdown

x=\frac{-b\pm\sqrt{b^2-4ac}}{2a}

~

常见数学命令：

| 命令 | 含义 |
|---|---|
| \frac{a}{b} | 分数 |
| x^2 | 上标 |
| x_1 | 下标 |
| \sqrt{x} | 平方根 |
| \sum | 求和 |
| \int | 积分 |
| \alpha | 希腊字母 α |
| \beta | 希腊字母 β |
| \rightarrow | 右箭头 |
| \pm | 正负号 |

> [!NOTE]
> ... 和 ... 属于常见数学扩展语法，并非所有标准 Markdown 渲染器都支持。ATLAS 是否完整渲染数学公式取决于其实际实现。

17. Obsidian 双向链接（扩展语法）

Obsidian 支持通过双中括号建立笔记之间的链接。

~markdown
微生物学

Python 基础

分子对接
~

指定显示名称：

~markdown
Python 学习笔记
~

链接笔记中的标题：

~markdown
微生物学#细菌的结构
~

嵌入其他笔记内容：

~markdown
实验记录
~

这些功能适合构建具有知识关联关系的笔记系统。

> [!WARNING]
> 双链 和 嵌入 属于 Obsidian 风格语法。GitHub 和其他 Markdown 渲染器不一定支持。ATLAS 中不要直接假设 Obsidian 双链会被自动解析为内部档案关联。

18. YAML Front Matter

YAML Front Matter 是放置在 Markdown 文件开头的结构化元数据。

示例：

~yaml
---
title: "Markdown 学习笔记"
category: tools
tags: [Markdown, Obsidian]
status: learning
---
~

常见字段：

| 字段 | 用途 |
|---|---|
| title | 文档标题 |
| category | 文档分类 |
| tags | 标签 |
| status | 学习或维护状态 |
| created | 创建日期 |
| updated | 更新日期 |

YAML Front Matter 必须位于文件最开头，通常由两行 --- 包围。

对于 ATLAS，还必须遵守其专门定义的字段、分类、ID 和关联约束。

> [!IMPORTANT]
> YAML 是独立的数据序列化格式，不应把任意 Markdown 正文语法直接套用于 YAML 字段。ATLAS 的 prerequisites 和 related 在未知关联 ID 时应保持 []，避免构建校验失败。

常见排障与避坑指南

问题 1：标题没有正确显示

现象 → 输入 #标题 后，文本仍然是普通文字。

原因 → 标题标记与文字之间没有空格。

解决写法 →

~markdown
正确标题
~

问题 2：文本高亮失效

现象 → 重点 直接显示等号。

原因 → 当前 Markdown 渲染器不支持高亮扩展。

解决写法 →

~markdown
重点内容
~

需要跨平台兼容时，优先使用加粗。

问题 3：加粗或斜体没有生效

现象 → 星号没有被正确解析。

原因 →

- 标记未成对闭合。
- 标记位置不正确。
- 编辑器处于源代码显示模式。
- 某些复杂的嵌套强调存在解析差异。

解决写法 →

~markdown
这是正确的粗体

这是正确的斜体

这是正确的粗斜体*
~

问题 4：复选框没有显示

现象 → 输入 -[ ]任务 后没有生成复选框。

原因 → 缺少必要的空格。

解决写法 →

~markdown
- [ ] 待完成任务
- [x] 已完成任务
~

问题 5：代码块无法关闭

现象 → 后续全部正文都变成代码。

原因 → 起始代码围栏没有对应的结束围栏。

解决方法 →

检查代码块开头和末尾是否使用匹配的围栏，结束围栏应独占一行。

代码块也可以统一使用三个波浪号：

~text
~python
print("Hello")
~
~

问题 6：表格排列错乱

现象 → 表格单元格合并、错位或无法渲染。

原因 →

- 缺少表头分隔行。
- 列数不一致。
- 单元格内出现未转义的竖线。

解决写法 →

~markdown
| A | B |
|---|---|
| 1 | 2 |
| 3 | 4 |
~

问题 7：换行后文字仍然连在一起

现象 → 源文件中已经换行，但渲染结果仍为同一个段落。

原因 → 普通换行可能被解释为软换行。

解决方法 →

如果需要新段落，在两段之间保留空行。

如果需要在同一段落内强制换行，可以在行末添加两个空格，或使用反斜杠。

问题 8：图片无法显示

现象 → 显示图片替代文字或图片加载失败。

原因 →

- 路径错误。
- 文件不存在。
- 路径大小写不匹配。
- 外部图片地址失效。
- 图片文件没有随文档一起部署。

解决写法 →

~markdown
图片说明
~

检查 images 目录是否存在，以及文件名是否完全一致。

问题 9：Obsidian 中正常，GitHub 上显示异常

现象 → 高亮、双链或嵌入内容在 GitHub 中无法正常显示。

原因 → 不同 Markdown 渲染器支持的扩展不完全一致。

解决方法 →

1. 优先使用标准 Markdown 语法。
2. 将 Obsidian 双链替换为普通 Markdown 链接。
3. 将 Obsidian 嵌入替换为标准图片或链接语法。
4. 对高亮内容使用加粗等更通用的标记。
5. 在最终目标平台预览文档。

验证清单

- [ ] 能独立编写包含一至六级标题、加粗、斜体、删除线、列表和引用的 Markdown 文档。
- [ ] 能正确使用任务列表、超链接、图片、表格和带语言标识的代码块，并理解常见编辑快捷键。
- [ ] 能识别 Obsidian 扩展语法与通用 Markdown 语法的区别，避免跨平台显示异常。
- [ ] 能使用 YAML Front Matter 创建符合 ATLAS 规范的笔记，并在知识库中正确渲染。
